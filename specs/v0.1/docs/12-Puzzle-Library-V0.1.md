# Puzzle Library 0.1.0

本增量不改变旧 `grid-push` / `grid-slide-merge` JSON 的行为或 exact hash；所有玩法在共享 Runtime 内执行，Adapter 只消费 PresentationFrame。参考关卡用于验收机制，不等同于 G01–G10、G20、G24 的完整游戏及 Agent Gate。

## 合同与边界

`a2game.puzzle.swap` 实现相邻交换、MatchN、Cascade、GravityFill；`tray` 实现有向遮挡、容量和三张消除；`pair-match` 提供记忆翻牌和有侧边可取约束的麻将变体；`direction` 检查箭头射线；`placement` 提供目标归位或 Polyomino；`falling-piece` 提供旋转、碰撞、下落与消行；`sort` 提供容量和连续同色倾倒；`connected-match` 提供连通消除及悬空掉落。`push`、`slide` 复用既有实现并增加可选撤销。

`a2game.puzzle.sort` 的 `width` 是管数，`selectActions` 按管索引一一对应；`tubes` 必须有 `width` 个数组，末尾为管顶，颜色值非零。容量为 `capacity`，未配置时取 `height`。选择非空源管后选择目标：目标为空或管顶同色且未满时，倒入源管顶部连续同色段，直至目标满或该段倒完；非法选择可清除选中状态，但不产生成功移动。每次成功倒液后，`moves` 加一，`score` 是已满且全为同色的管数，不计空管。默认胜利条件是每管均为空或已满且同色；配置 `targetScore` 时达到该分数也会置 `won`。`score` 和默认胜利条件在成功倒液后更新，不应假设初始状态会自动按管数计分。

2026-10-27 顶出修复：`falling-piece` 硬降或重力锁定后，在同一事务中消行、生成下一块并检查出生位置；出生被占用立即置 lost，不能用该 Tick 的后续移动或下一 Tick 移动逃离重叠位置。进入 Tick 时已经被占用的出生位置同样先判失败。此前实现的检查延迟允许移动规避顶出，本次修复不改变合法拼块的移动、旋转、重力周期和消行规则。G09 revision 3 使用空 4×8 棋盘、四个 tetromino 连续消四行；变体 revision 3 改变序列并加快重力。原单拼块样例与旧回执保留，完整人工质量与独立 G3 另验。

每种行为有独立 Manifest/config Schema、必需能力依赖和参考 GameSpec。内部 `grid`、`occupancy`、`match-n`、`cascade`、`gravity-fill`、`layered-stack`、`occlusion`、`reveal`、`polyomino`、`rotate-piece`、`line-clear`、`select`、`undo`、`merge` 声明算法服务；这些不是供 JSON 执行任意命令的解释器。`core.goal/rng/score/timer` 声明 Runtime 既有服务。

棋盘最大 16×16、256 格；拼块最大 4×4、16 格；级联和撤销历史各最多 16 层。非法交换、遮挡选择、越界、错误颜色和碰撞不产生成功移动或消耗补位 RNG。遮挡关系必须无环；配置引用的 Action 必须存在。记忆翻牌按逻辑 Tick 延迟关闭，暂停冻结；下落同样只使用唯一 Tick。

撤销恢复模块状态及 RNG，限单行为场景。多行为组合需要使用整个 Session Snapshot；不能局部回退共享 RNG 而保留其他行为的随机结果。撤销下落时该 Tick 不额外推进重力。初始历史必须为空，存储路径必须独立。

## 输入、画面与验证

参考 JSON 通过语义 Action 选择格子，播放器按 Action 定义生成通用按钮，支持键盘及 DOM Pointer。选中、托盘、预览和棋盘通过只读投影显示；不存在按游戏 ID 的 Adapter 分支。DOM 移动视口验证不代表真机 Touch、原始命中测试或拖动手势验收。

`project/puzzle-reference-cases.json` 固定手工预期的合法解和非法输入；`npm run puzzles:e2e` 在真实 HTTP Three.js/CocosAirJS 各运行 12 份 JSON，核对 Node 操作回放 Hash、暂停、胜利、重开、截图、错误日志及释放。回执包括源码/SDK 指纹、浏览器和输入操作，独立保存每次运行。`test/puzzle-library.test.mjs` 仅保留随机撤销、遮挡/记忆、旋转消行和分类守恒等必要回归；Conformance 对各机制保留正反例。

## 2026-10-27 完整滑动对局

`puzzle.slide` 与 `grid-slide-merge` 可选 `stalledPath` 指向独立 bool：棋盘满且横/纵无同值邻居时为 true。空位、合法合并和无效方向均按同一共享算法判定；无效移动不消耗随机。可撤销 Profile 同时保存该字段与棋盘、best、RNG，不改变旧配置。G02 revision 3 从两个 2 开局，种子 42 的作者搜索回放分别 957/1872 步到 2048/4096，182 步达无路失败；作者搜索不计独立 G3。回放原始动作在 project/full-2048-traces.json。

## 扫雷棋盘

`a2game.puzzle.mine-board@0.1.0` 支持 3–8 列、3–8 行。每格对应一个 button Action，`flagAction` 切换揭格和插旗。状态中的 `mines` 存格号，`tiles` 按行优先保存覆盖（−2）、旗标（−1）、已揭邻雷数（0–8）或触雷（9）。表现只投影 `tiles`。首揭若原位置有雷，用共享 RNG 将该雷迁到另一空位；旗标与重复揭格不消耗这次保护。后续触雷立即判负，揭完全部安全格判胜。[G35 正反例](../../../games/coverage-v2/g35-lantern-minefield/conformance.json)

## 重叠牌面与点选

`a2game.puzzle.tray` 可用 `tilePointer` 声明单一 `touch.raw` 动作、场景尺寸、牌面尺寸和按从底到顶排列的牌中心。此时 `selectActions` 为空，`blockers` 必须与高层矩形重叠一致。触控只选择点击位置最上方的未移除牌，当前被遮挡则拒绝，移动超过 350 个逻辑单位、取消或多点介入不触发选牌。成功选牌先归组和消除，再检查槽满。Scene2D 用同一中心和牌面尺寸投影，已移除牌在呈现中省略。

可选 `trayTools` 使用固定牌位置索引作为身份，`faces` 保存各身份的图案。同一身份在棋盘、槽、保留区或已消除区中恰好出现一次。移出三张保留原顺序、清除旧撤回点且不加分。取回走普通选牌事务。撤回恢复最近一次选择前的牌及 RNG，并扣除撤回额度；胜利须清空三个可玩区域。旧内容继续沿用原槽位和撤销逻辑。

声明 `trayTools.shuffleAction` 后，每局可提交一次洗牌。构造器先补齐槽中的同类半组，再按遮挡拓扑和剩余牌面构造合法消除次序。候选只改变棋盘未取牌的图案，保持位置、牌 ID、槽、保留区及图案多重集。无法构造或排列无变化时，保留布局、额度、撤回点及 RNG；该结果不判定为无解。洗牌成功后清除旧撤回点，游戏画面不展示构造出的路线。

独立且无计时规则的道具叠牌可启用 `journalActions`。模块在成功事务事件中提供牌 ID 或已声明道具动作。参考播放器为同源存储按 GameSpec 摘要隔离记录，最多保存 512 个成功事务。恢复时核对能力目录摘要，按紧凑 Tick 从原始游戏重放，校验牌局及 RNG 摘要。坏记录保留并给出重试提示。用户明确重试时从初态开始，胜败结算后清除局中记录。

## 有限步数颜色目标

`a2game.puzzle.swap` 可同时配置 `moveLimit` 和 `colorGoals`。初态 `goalRemaining` 对应各目标的声明顺序，`movesRemaining` 等于步数上限。有效交换在所有连锁结束后扣一步；每枚实际消除的普通棋子加 10 分并计入对应颜色目标。最后一步完成全部目标则胜，耗尽且目标未完成才失败。非法交换不消耗步数或 RNG。此配置与旧 `targetScore`、`undoAction` 互斥。

在颜色目标配置下可启用 `specialBlocks`。按行优先保存 `specials`、`pieceIds` 与新 ID 游标。相交连线合并后，五连颜色清除优先于 T/L 爆炸，再优先于四连直线。首波先选交换目标格、源格，再选最小普通棋子格；后续波从最小候选格开始。转化产生新 ID 并在本波保留，转化不计分。已有特殊块受击按稳定队列激活，每个 ID 只消耗一次；直线清行或列，爆炸清中心 3×3，颜色清除块可与普通棋子交换，或在受击时取本波占比最高的颜色（并列取最小 ID）。

相邻特殊块交换优先触发组合，两枚配对块各消耗一次，并发出 `puzzle.special-combined`。以交换目标为中心，双直线清行列，直线加爆炸清中心三行和三列，双爆炸清 5×5，双颜色清除块清全盘。颜色清除块与直线或爆炸组合时，将配对颜色的其他棋子转换为对应种类，保留原 ID，并按 ID 升序激活。首波不另算配对块的单体效果，也不生成普通匹配的新块。击中的其他特殊块可继续触发，且按棋子去重。

启用特殊块时可配置 `obstacleGoals`，按格分别保存 `ice` 和 `boxes` 的 0–3 层。冰叠在格底，该格被匹配或被特效覆盖时可扣层；箱体占格，受特效直接命中或相邻普通匹配消除时可扣层。每格每波最多扣一层，每层 20 分。箱体尚存时该格禁止交换，所在列分段下落，仅与棋盘顶部连通的段补充新棋子。目标需同时满足颜色和障碍层计数。

`outletLayout` 可在特殊块棋盘中声明互不重叠、自上而下且上下相邻的重力路径。路径外的格为孔洞，禁止交换和补充。每条路径只有与棋盘顶行相连的区段补充新棋子，箱体仍可分隔区段。`outlets` 只能引用路径末格。面值 14 的收集物保留原棋子 ID，不参与颜色匹配，也不会被特效清除。它落到指定出口后从棋盘移除，每件加 50 分，递减 `collectionRemaining`，并发出含棋子 ID、出口格和波次的 `puzzle.outlet-collected`。通关须同时完成颜色、已声明的障碍与收集目标。

独立有限步数三消可以启用 `journalActions`。每次成功交换在 `puzzle.changed` 中携带起止格，播放器按同源、GameSpec 摘要及能力目录摘要保存和重放已提交的交换，并校验棋盘、步数、目标及 RNG。重试和终局清除局中记录。

有限步数三消可启用 `deadboardShuffle`。开局及每次交换结算后，若目标未完成且还有步数，检查棋盘是否存在合法交换。死局时用共享 RNG 尝试最多 64 种排列，保留棋子身份、收集物位置、孔洞、障碍、目标、步数和得分。候选棋盘必须没有现成连线且有合法交换。`puzzle.deadboard` 记录是否恢复和尝试次数，无法恢复时判负并允许重试。

特殊块关卡可用 `matchTools` 声明锤子、强制交换、洗牌和取消按钮。初始 `toolRemaining` 分别记录三类库存，每类最多 8 个。`toolMode` 只表示尚未提交的选择。锤子直接击打一个普通棋子、特殊块或箱体，并使用同一命中与计分规则。强制交换可交换相邻可移动格，即使不会形成匹配，空格、箱体及无实际效果的同类型同色交换会被拒绝。手动洗牌须产生有合法步的稳定新棋盘，失败时恢复 RNG。取消、无效和库存耗尽均不扣道具。三个道具均不扣普通步数，成功提交后发出一次 `puzzle.tool-used`。启用事务存档时，播放器在恢复中重放成功道具操作并校验剩余库存。

有限步数关卡可设置 `settleTicksPerWave`（1–24）。交换和命中仍在同一 Tick 原子提交。`puzzle.resolve-wave` 提供各波格位，`puzzle.resolving` 提供播放顺序的总时长和交换格。`settleUntilTick` 是首次可接收下一操作的 Tick。在此之前，棋盘与道具动作被丢弃。此模式下的 `touch.select` 必须启用 `gestureMetadata`，以便拒绝在输入锁定期间开始、解锁后结束的拖动。暂停停止 Tick 和波次高亮。减少动态效果只关闭表现。刷新时重放已提交事务并从稳定棋盘继续，省略已提交动作的旧动画。

## G35 扫雷扩展

`a2game.puzzle.minesweeper@0.1.0` 运行在共享 simulate 阶段。棋盘宽高各 2–8 格，雷数为 1 至总格数减 1；`cellActions` 按行从左到右绑定每格，另设独立按钮 `flagModeAction`。`statePath` 绑定独立顶层 object；初始状态为 `mines=[]`、全部格子 `-2`、`flagMode=false`、`remainingSafe=总格数−雷数`、`status="playing"`。每次重开由 Runtime 恢复初始状态及种子。

首次有效揭开时，使用共享 RNG 从除所选格外的位置无放回抽取雷位。只保证所选一格安全，不保证它的相邻格也无雷。插旗、取消旗或揭开已插旗格不会消耗 RNG；插旗不参与抽样。空区按八邻域展开并显示相邻数字，不会翻开旗格。全部安全格已揭开时获胜；踩雷时仅标记被踩格并失败。所绑定动作为按下边沿，终局忽略后续动作。

展示只绑定公开的 `cells`、`flagMode`、`remainingSafe` 等状态。格值 `-2` 为覆盖、`-1` 为旗、`0..8` 为已揭开的邻雷数、`9` 为踩雷。禁止在表现绑定中使用 `mines`；该数据仍存在于本地逻辑和快照，不是服务端防作弊或多人隐藏信息。两个独立参考 GameSpec 分别用 4×4/3 雷和 5×4/4 雷验证同一能力；不计入原 32+5 的冻结范围。
