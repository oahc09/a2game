# 宿主发现与触发

技能存在、被发现、被选择、成功调用工具是四件事。宿主可能缓存旧描述；本地文件检查只证明布局，不证明会话已重载。

唯一维护源为 `integrations/skill/a2game/`。已配置的项目发现位置：Qoder/ZCode 为 `.agents/skills/a2game/`，TRAE 为 `.trae/skills/a2game/`，WorkBuddy 为 `.codebuddy/skills/a2game/`。这些是本项目的接入路径，不能推定所有宿主版本都已验证。不要为触发测试改全局配置或安装新技能。

当用户授权接入检查时，先只读核对对应副本与源码 SHA，再在宿主新会话看可用技能目录。存在旧副本差异时报告差异，由维护端增量同步；不要盲目覆盖。MCP 另用真实工具发现确认；Skill 可见不等于 MCP 已连接。

最小触发验证按实际需要选用，不批量启动宿主或模型：

| 场景 | 示例请求 | 应观察的行为 |
|---|---|---|
| 自然语言隐式触发 | 在此 A2Game 项目做一个太空快递小游戏，能失败、能重开 | 自行选择技能、查询能力、设计新作品，不要求用户补写 `$a2game` |
| 已有作品改进 | 改善这个 A2Game 游戏的手机画面和操作反馈 | 先读原稿，实际预览并按问题修订，保留来源 |
| 显式触发 | 使用 `$a2game` 校验我提供的 JSON | 读取技能并执行要求的校验，不额外调用 Provider |
| 不应触发 | 用 Phaser 实现小游戏；修复 Three.js 引擎渲染器 | 沿用用户指定引擎或开发流程，不改成 A2Game JSON |

隐式测试开始前不要告诉 Agent 技能名、入口路径或预期选中的技能；否则只算显式指导。自然语言触发应在已知 A2Game 工作区进行，不把任意“做个游戏”扩展成全局抢占。

记录宿主及可核实版本、会话、实际用户提示、可见技能描述、是否读取技能、第一条能力查询和工具别名、结果及原始导出位置。没有宿主暴露的读取记录就写 `UNKNOWN`；仅看到正确作品不能倒推出技能被触发。显式成功、隐式成功、工具可用性分别记录；旧会话或其他宿主的通过不能互相代替。真实宿主执行需要对应授权与用量记录，不从文档示例推导新增额度。
