# 作品质量与素材

质量审查以实际操作与截图为依据。当前项目采用 Agent 试玩→问题记录→修复→主审复核；这不改变独立来源、完整调用链或适用设备要求。仅修改作品时保留作者原稿，另存修订，不改 Runtime/Adapter 为某个游戏硬编码玩法。

## 完整可玩循环

玩家进入后能读懂目标和主要操作，有安全读屏期；实时敌人/倒计时不应在读完说明前立即造成不可逆失败。准备期要结合实际 Tick 和正常时钟试玩决定，不套固定秒数，不靠暂停或快进截图掩盖节奏问题。

主要动作应有可见结果：选中、移动、命中、资源消耗、建造、合成或无效操作反馈来自真实状态。成功、失败或中立结束要明确，暂停、恢复和重开可操作；不适用失败机制时保留有意义的未完成负例，不强造败局。难度、选择和进程应支撑用户要求的玩法；增加按钮、装饰和数值不等于更完整。

## 画面与输入

用统一主题、少量主色与强调色区分背景、可交互对象、危险、目标和文字。优先保证棋盘/角色/操作目标的空间，再放 HUD 与说明。静态说明、动态数值和结果区层次清晰；不能只靠颜色区分对象，也不能泄露应隐藏的牌面/信息。

scene2d 为中心原点、Y 向上，完整棋盘和文字边界须在 `[-width/2,width/2] × [-height/2,height/2]` 内。投影、可点击格位与图形边界一致；炮台、子弹、标签与 HUD 不互相遮挡。字体调整后重新检查长文、动态数字、多位数和终态，不只看首屏。

在用户要求的尺寸上检查；未指定手机尺寸时，桌面加一个 390px 窄屏即可，内容仍有风险再补 320px，不机械扩大矩阵。动态缩放等待 SDK 布局完成后再截图。重要文字建议接近可读的 16 CSS px、触控目标建议约 44 CSS px，但最终看实际字形、遮挡和可操作性；scene 字号不等于 CSS 字号。`getTextReadability()` 仅供定位，绑定与返回方式见 [工具流程](workflow.md)，无 warning 不是质量通过。

实际测试声明支持的键盘/Pointer/触摸路径；DOM 按钮通过不能代替画布点选通过，API 注入通过不能证明键盘有效，CDP/合成输入不能计真机。按住时保持视口，避免截图过程改变命中坐标。实时玩法至少一次用正常 Tick 调度试玩，验证准备期、节奏、输入释放和输赢反馈。

## 素材选择与接收边界

先确认目标宿主真实支持的表现能力和可用审核资源。几何、文字、调色和通用投影可支撑清晰的风格；用户明确需要图片/声音时，不能把无素材占位稿称为完成。按[工具流程](workflow.md)发现服务实际列出的creation-library资源，或使用可信控制端提供的审核清单/安全摘要，并查询对应Capability，不编造asset ID或URL。当前创作主题条目只支持其声明的kind：scene2d-authoring-theme是需适配的图元/preset，不等于图片、音频或3D素材包均已就绪。没有可用目录/批准清单时将所需素材项记为NOT_RUN/BLOCKED，不越界读私有目录。

| 资源来源 | 使用方式 |
|---|---|
| 宿主已审核资源 | 按实际 URI、类型、字节数、SHA 和许可使用；通过完整准入再预览 |
| 用户提供或新制作素材 | 先交可信维护端审核/登记，核实格式、许可、透明/方向、尺寸和实际可加载性 |
| 无兼容资源或无制作授权 | 如实标注素材缺口；可交可运行的风格化几何稿，但不把占位/缺失写成最终高质量素材 |

不自动下载任意 URL、调用付费生图/配音、安装资源包、修改白名单或扩大模型额度。内容包不嵌入 Runtime 或资源二进制；导出成功不保证接收方拥有素材。交付前列出接收端所需的兼容宿主、SDK 与审核资源。SHA 是完整性校验，不是作者身份或版权证明。

若主题图元已完整内联进GameSpec且没有外部资源引用，接收方不需要原主题JSON，但应保留主题来源/许可记录；若GameSpec保留资源引用，接收方仍需相应批准资源及完整准入。不要把这两种交付方式混为“导出包自动带齐素材”。

## 试玩、修复与复核

先准备操作序列，逐个打开 Air/Three 预览，保留初始、核心过程、成功及适用失败状态的截图、实际动作、关键状态/同 Tick Hash、控制台问题。及时显式关闭本轮每个预览；过期不是显式关闭。缺 SDK 或浏览器工具时对应项写 `BLOCKED/NOT_RUN`，保留其他可复现结果。

问题记录只需包含“现象/截图→影响→修订→复核结果”，不新建评分系统。例如“准备期内敌人已到终点→尚未读完说明即失败→作者另存新稿调整波次→正常时钟重测”。修订后重新完整准入和测试，再核对两个 SDK 的实际效果；若声称仅改表现，另核对输入、状态、规则、测试和解法没有变化。改节奏/规则应如实标为玩法修订。

原始输入试玩可分两种互补证据：手动逻辑时钟下以真实键盘/DOM操作、记录输入和推进Tick，再在Node按原始记录逐步回放Hash；正常时钟下实际操作确认读屏、节奏与反馈。不要拿两个任意时刻的正常时钟Hash直接比较，也不能把手动时钟的可控结果说成已经验证正常节奏。

复合游戏还要检查阶段切换：准备/生产中/待收取/合成后/升级后/胜负文案与当下状态一致。固定“首杀奖励/现在升级”提示不能无条件套用所有reward事件；零奖励击杀、后续波次和末击都可能留下过时指令。奖励已花费、等级已提升或游戏已结束后，应给出结果反馈。核对真实状态、可见文字与画面，不能只以最终won通过。

修反馈时注意规则时序：所有T7条件和右值读取同一S_sim；priority只在同一事件的匹配规则间排序，不能跨eventIndex盖过较晚事件。用实际阶段/状态/事件条件限制提示，避免通用奖励事件覆盖升级或终态摘要；不靠无限提高priority掩盖竞争。正常时钟至少跑完整一局，验证准备时间足够完成所要求的读屏与投入，不能只快进到结算。

实时操作手感应在安全空场校准：按住方向是否持续响应、松开后短时间位置是否继续变化、暂停恢复是否带着旧输入、射击是否真正跨多个冷却周期。最终vx为0可能只是撞到边界，不能代替松开后的位移检查。手动Tick可核对每Tick位移和排队边界；正常时钟再验证边移动边射击与成长，自动化命令往返时间不当作端到端输入延迟基准。

虚拟多指应分别验证“松开移动指，射击仍继续”和“松开射击指，移动仍可独立控制”，检查实际送达的pointerup/cancel/lostpointercapture与后续位移，而非仅看控制API调用成功或最终通关。CDP版本/驱动的触点列表语义可能与预期不同；先用小探针观察当前浏览器事件，再归因Host/Runtime，不把驱动失控算成游戏缺陷，也不把isTrusted当物理设备证明。持有触点期间固定视口和坐标映射。

视觉审查还要看有效战斗区域占比、弹丸尺寸/轨迹、命中/受伤闪光与成长配色；字号达标仍可能被重复说明挤掉主战场。删减画布内重复文案可在保持玩法不变的前提下扩大有效投影，改完需看真实画面。realtime身体的value可能是击杀分值或弹丸damage，不能直接标为敌HP；按生产者合同绑定显示意义。

卡牌需区分位置号与牌面类型，手牌左移后控件仍按当前索引工作；不要只用颜色编码。允许画布点牌时，使用已注册的contain-space命中合同，按实际canvas矩形/场景适配换算坐标，并验证边框留白、空位置、满手和实际出牌；DOM按钮通过不替代画布命中。资源透支、风险越界或超过次数时应突出失败条件，即使目标计数已达标；说明文字不能漏掉某类实际败局。

手动step返回只证明逻辑推进完成，不证明原生SDK已经绘完。手动时钟、resize或截图方式变化后等待实际原生帧再抓图；必要时采用固定视口截图，避免全页捕获的视口/滚动影响。黑画布/旧帧必须作为失败图保留并查看补拍，不能因脚本PASS跳过审图；多个捕获条件同时调整时不宣称已单独定位某个因素。

释放诊断要按所有权层级读取：当前 `diagnostics().resources.ownedResources` 是资源作用域计数；Air适配器是 `adapter.ownedNodes`，Three是 `adapter.ownedMeshes`，另核对适配器/资源的disposed、listenersActive及预览URL关闭。不能假设两个适配器都有 `adapter.ownedResources`；缺字段不按0处理。Scene-owned计数归零不证明引擎共享缓存、AudioContext或全部GPU内存零泄漏。CLI预览结束与页面SDK释放也要分开记账。

最终分开报告功能、视觉/操作、素材、节奏/完整度；逐项写已检查证据和遗留问题，不从总分或通关推定全过。当前主审可直接承担复核；已有 Worker 时核对其原始证据，不能把同一份作者自评复制成独立主审。没有实际试玩/截图、素材仍缺失或关键操作不可用时，质量保持待完善；Agent 质量通过也不自动升级正式 G3、独立性、物理设备或远端 CI。
