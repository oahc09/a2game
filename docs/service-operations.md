# 单管理员服务：启动、恢复与部署准备

本轮实现有界单实例服务：管理员登录、发布权限、持久化生成队列、版本恢复和HTTPS反向代理入口。仍需执行实际TLS/部署和外部验收；本说明不代表已上线，也不提供多用户或多租户账户。

## 本机启动

安装依赖、构建并准备锁定SDK后，由宿主创建配置：

```json
{
  "releases": [],
  "providerId": "fixture",
  "maxCalls": 0,
  "allowPublish": false,
  "stateDirectory": ".a2game/creation-service",
  "adminTokenEnv": "A2GAME_ADMIN_TOKEN",
  "port": 8790
}
```

宿主通过运行环境提供至少32字符的随机管理员令牌；配置只写环境变量名，不写令牌值。执行 `npm run delivery:serve -- .a2game/service.json`，打开输出地址后登录。登录使用20分钟的HttpOnly、SameSite=Strict会话；退出或服务重启后原会话失效。令牌不写入任务状态、URL或浏览器本地存储。连续登录失败有限流。

`allowPublish:false` 禁止发布，管理员也不能通过网页改成true；只有宿主启动配置可开启。网页继续不能修改Provider、命令、路径或预算。默认fixture是固定演示，不计真实模型生成。需要真实模型时沿用原Provider配置和另行明确的预算；本轮没有新增真实调用。

## 持久化与队列

`stateDirectory` 仅允许工作区 `.a2game/` 或 `output/` 下的非符号链接目录，推荐 `.a2game/creation-service`。未配置时保持原临时会话行为。状态文件使用摘要、有界大小、临时文件、fsync及原子替换；单写者租约防止两个实例同时写入。

- 单Worker顺序执行。任务列表上限16，包含终态历史；版本记录上限16，不能作为无限历史或分布式队列使用。
- 生成请求排队时同时保存请求和预留额度，再启动Provider；原始请求不进入公开任务API。导入游戏包仍要求Worker空闲。
- 取消尚未执行的排队任务可退还对应预留；已开始任务按实际报告或未知上限计入。重启不会刷新累计已用/预留额度。
- 重启后恢复排队请求前核对Provider配置摘要和当前预算；配置变更或预算不符时标记中断，不自动切模型。已开始但中断的任务不自动重跑。
- 已完成任务恢复时重新执行验证；发布SDK重新完整准入并比对可信源码、资源与逐文件SHA。损坏或源码过期的版本进入恢复拒绝清单，不向客户端下载。
- 选版状态保存并恢复；发布或选版持久化失败时回滚相应内存变更。任务存储故障会阻止继续生成或导出。

## 恢复与升级

停止服务后，备份整个 `.a2game/` 和 `output/`，连同匹配的源码、依赖锁、SDK及审核资源。任务文件位于状态目录下的 `jobs/`，发布SDK目前仍位于 `output/`；只保存状态索引不足以恢复发布物。容器部署需要持久化这两个目录。

正常重启使用同一状态目录。确认为已退出进程的旧租约会移入保留目录；无法确认的租约或损坏状态会使启动失败，先核对进程及备份，不清空额度台账。状态曾初始化但主文件丢失时拒绝从零开始。摘要用于发现字节损坏，不认证操作者身份；存储目录只应允许服务所有者写入。

源码升级导致旧SDK拒绝恢复时，可在管理员开启发布权限后，重新发布仍通过当前验证的已完成任务，从原内容生成新SDK；不需要重新调用模型。旧文件保留。未实现无限历史归档管理，达到有界容量后需单独规划保留与迁移，不能通过删台账或换空目录规避已授权额度。

## HTTPS反向代理入口

对接外部HTTPS入口时，宿主配置再加：

```json
{
  "publicOrigin": "https://games.example.com",
  "signingKeyEnv": "A2GAME_DELIVERY_SIGNING_KEY"
}
```

这两项应合并到前面的配置中。`signingKeyEnv` 指定由运行环境提供的Ed25519 PEM私钥变量；也可通过Node API提供宿主签名函数与公钥。未配置管理员、持久存储和签名时，HTTPS模式拒绝启动。本轮仅用内存测试密钥验证，没有配置生产令牌、私钥或证书。

应用始终监听 `127.0.0.1`。TLS网关与应用部署在同一主机；网关须转发规范Host、由网关设置 `X-Forwarded-Proto: https`，并保留浏览器原始Origin。应用检查固定公开来源后再交给原有同源处理链；错误Host、Origin、协议和跨站请求被拒绝。HTTPS模式使用Secure会话Cookie及签名交付清单。接收方信任HTTPS启动配置中的公钥；摘要与签名均不能证明模型或作者身份。

实际域名、证书、网关配置、网络开放、生产密钥及部署需单独安排。本轮只验证了代理头约束和签名协议，没有把模拟请求当作真实TLS验收。单写者服务不支持多副本共享状态目录。

## 验证入口

`node --test --test-concurrency=1 test/service-persistence.test.mjs test/service-queue.test.mjs test/admin-boundary.test.mjs` 检查恢复、排队/取消、预算、登录、发布开关与代理边界。`node scripts/air-layout-smoke.mjs` 使用锁定真实SDK核对可见、隐藏及恢复路径。这些定向回归不升级正式G3、全目录验收或真机计数。
