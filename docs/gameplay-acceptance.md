# 逐款玩法完整验收

本表依据 PROJECT-PLAN.md 的最小 DoD，分别跟踪全部 32 款游戏与 5 款混合玩法。每款定义、边界操作与作者变体见 [机器清单](../project/gameplay-acceptance.json)。

## 统一完成标准

1. 明确玩法、交互、胜负、视觉与禁用/边界行为。
2. 完整 Schema、语义、Capability、资源和来源检查。
3. 正反例、确定性回放、暂停、重开和失效清理。
4. 真实双 SDK 的用户交互、胜负、重试、画面和生命周期证据。
5. 独立 Agent 从自然语言生成规则变体，记录提示、输出、修复成本和可玩性。
6. 以对应 CoverageResult 及适用真机证据升级正式登记。

`gameplay:check` 执行基础正/负例、边界、作者变体正/负例，并补充 G11 偏心连击重置、G24 竖线/双斜/和棋，另覆盖移动水果漏果、校准/姿态失联回退，共 193 个场景；每个场景检查暂停、快照和逐操作 Hash 重放，终局拒绝继续输入。`candidates:e2e` 复用相同附加场景，检查 Node/Host/跨引擎 Hash、终局冻结和截图；`variants:e2e` 独立覆盖作者变体。两者通过完整 Schema 校验后的 SHA 内置目录运行真实 HTTP/SDK；动态未入目录 JSON 的完整准入由 `content:e2e` 单独覆盖，带资源的目录关卡仍需完整资源准入。

**必需玩法缺口已降至 0 款；完整 verified 仍为 0/32、0/5。** 作者变体不计独立 G3；非空画面、AI 截图检查和窄屏检查不替代完整人工可玩性审查。物理任务按用户要求暂缓。最后一栏列出尚待完成的正式验收 Gate；机器清单的 `remainingGameplay` 单独统计必需玩法缺口。额外内容建议在机器清单的 `futureIdeas` 中，不作为新增门槛。
