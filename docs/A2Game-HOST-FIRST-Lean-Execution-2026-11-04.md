## 前一阶段执行顺序（历史，2026-11-06）

1. **当前：整理WorkBuddy的G03三消执行任务。** 复用现有run/capsule工具准备独立目录和启动绑定，先确认本轮宿主原生模型额度，再启动创作；不复用G01的hostRunId。不重复G01或基线测试，也不把准备任务视为授权消耗新模型额度。
2. **G03：先做出可玩的新三消。** 由WorkBuddy创作，执行现有MCP校验、测试、双SDK试玩及导出。最少检查一次合法交换消除、一次非法交换不错误结算，以及暂停/重开/预览关闭。仅出现实际问题时追加定向检查，保留原失败与修正版。以同Tick输入回放比较完整Hash，不比较任意墙钟时刻的Hash。
3. **按真实失败修复，再扩展玩法。** G03可玩后，按G17纵版射击→G21塔防→H01合成炮台逐款推进；每次只开展一款，分别检查移动开火/结束条件、建塔扣费/余额不足、合成生效/旧炮台停止攻击。每款双SDK各一个核心流程，不扩展三宿主矩阵。新调用均遵守对应明确额度。
4. **交付收口穿插进行。** 复用现有说明整理WorkBuddy最短“接入→生成→验证→游玩→导出”路径，保留可玩包和简短回执。新run执行前先验证实际服务绑定，防止再次在未绑定服务上完成整条链。
