# 多模型 G3 实测与技能反馈

目标是让 Qwen、MiniMax、GLM、DeepSeek 等模型分别实际生成同一组玩法任务，统一验证并积累可复现的成功/失败材料。模型家族名称只表达评测意向；精确版本、服务地址、宿主能力和预算尚未配置，当前没有这些模型的实测成绩。

## 三种执行模式

| 模式 | 实际生成者 | 当前状态 |
| --- | --- | --- |
| 原生子 Agent | 宿主明确选择的子 Agent 模型，直接生成JSON | 最小导入已实现（`scripts/g3-native-subagent.mjs`，2026-10-28 G01 首轮 3/3 预算工程 PASS_REFERENCE 待审查）；跨宿主/服务端身份确认与统一上下文导出仍未实现 |
| HTTP 模型服务 | 子 Agent调用配置中明确指定的provider/model | 已有 `g3:run` 和HTTP适配器；各厂商兼容性尚未预检，不代表已经接通 |
| Codex CLI | 已配置CLI实际选择的模型 | 现有路径可用；只能按其真实来源登记，不代替其他模型 |

其他AI作为调度器与它作为生成器是两种不同实验。若Qwen主Agent派子Agent去运行Codex，生成成绩归实际Codex模型。宿主不能选中目标模型或无法保证新会话隔离时，明确标记阻塞/未验证，不静默替换。

HTTP适配器当前按Chat Completions构造请求，并要求特定的消息、JSON响应、输出预算及结束原因字段。各服务可能需要适配；先以明确预算进行兼容预检，保留截断、参数拒绝、网络错误，区分ADAPTER/INFRA与模型内容失败。预检也记录实际调用，不猜测接口地址、模型版本或费用，不读取认证文件。

## 可比较条件

一个评测单元由provider/精确model版本、任务ID、变体ID、技能版本、公共上下文SHA与辅助Profile确定。按相同任务顺序逐款执行，每个单元跨批最多3次生成，所有模型共享本轮已批准的总预算；本设计预算仍为0。

公共任务包必须冻结提示、协议/Schema、能力ABI、允许的技能内容、Runtime/SDK版本、输入/输出/修复预算与辅助条件，保存原始字节及SHA。旧Codex HostProfile含额外公共ABI文本，普通HTTP请求与原生宿主上下文不一定相同；统一任务包跨入口导出尚未实现，不能把当前不同上下文的历史成绩直接排成公平排行榜。

原生宿主和API模式分组统计，记录无法控制的system提示、工具权限及上下文继承限制。模型requested ID、服务返回ID、宿主路由/执行证据分开保存；仅模型自报身份标为未验证。缺少真实版本或来源的产物仍可做工程诊断，但不能计为某已核验模型的成绩。

初次生成只提供任务和公共资料；后续只提供同规则下的诊断与该模型自己的旧输出。作者答案、其他模型解法和旧获胜轨迹不得进入独立生成。宿主BFS、Runtime搜索、预存轨迹及人工修复必须单列，不能混入模型自解成功率。

## 每个单元记录什么

- 原始请求/回复、提示/技能/上下文SHA、模型来源证据、全部尝试、终止/失败原因和修复链。
- 首次生成通过与预算内通过分开；完整准入、正反例、模型提供的解法、宿主辅助解法分别记录。
- 双SDK的当前定义SHA、Node/Host Hash、主输入、暂停/重开、截图及释放回执。
- 按统一标准审查玩法语义、指定变体、边界和画面，保存具体发现及AI参考结论；尽可能隐藏模型标签进行内容审查，无法盲审时如实记录，不改原始JSON。
- 生成、调度和审查的实际用量、耗时分别记录。验证重放不重复计为模型调用；未返回用量或没有价格依据时保持未知。

汇总展示原始分子/分母：计划、未运行、来源未验证、基础设施阻塞、首次通过、预算内通过、模型自解、主输入和AI质量审查。所有成功率明确适用单元和分母；NOT_RUN不当作失败，INFRA可用性和模型内容成功率分列。不同上下文、预算、技能版本或辅助方式不能直接合并成一个模型总分。AI参考通过仍不等于正式G3或人工/真机通过。

37任务×4模型家族是148个待配置单元，不是148个已执行结果；最多3次是单元上限，不是新增调用授权。新变体或技能版本增加新的单元，旧结果不覆盖。

## 从失败改进技能

1. 聚类真实问题：JSON/协议、能力选择、玩法状态、正反例、输入生命周期、表现、资源释放、接入与基础设施。
2. 审查根因属于模型、技能说明、公共ABI、Runtime、Adapter还是环境，绑定任务、版本和失败证据SHA。不能把引擎问题归罪模型，也不因某模型失败就削弱验收要求。
3. 形成技能修改建议：补充适用触发、约束、公共机制用法和必要反例。保留现有路由、用途、触发条件与数据边界；不把具体关卡答案写成技能，不自动修改全局Skill文件。
4. 冻结新的技能版本与SHA，先复验对应缺陷，再使用未参与改进的新变体做保留集评测；至少跨不同模型观察泛化。用同一批失败例改进后再测，只能称回归，不能冒充未见任务的一次成功率。
5. 比较技能版本前后对应单元，保留无效和退化结果；由独立任务验证后再接纳技能修改。

本会话负责结果审查和改进建议；跨宿主自动回传、统一上下文导出、原生结果导入、模型结果聚合器与技能自动升级均未实现。正式签收、真机与外部服务配置继续分别跟踪，当前设计不触发任何新模型或Actions调用。
