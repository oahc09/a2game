## 定位与启动条件

从“Agent能生成可运行游戏”推进到“Agent能持续创作高质量、可交付的游戏”。主要产出是实际作品、可组合素材、可嵌入播放器和版本化交付，不围绕测试工具建设系统。

本文已按用户新指令启动本地实施，不能把开工当作验收完成。当前WorkBuddy五款Agent质量参考、工程修正版及本地交付包已经存在，但真实多宿主、来源与独立性、完整原生调用链等现行Host-first未完成项仍保留。Qoder/TRAE的具体真实会话仍需实际记录，Orca Worker或当前宿主创作不得代称这些品牌宿主已通过。

启动范围以本次用户明确指令为准；旧约定缺项和真实环境阻塞继续分别记录。正式G3、37款全量verified、真机与历史失效证据不由第二阶段启动升级，也不临时增加“重跑所有历史报告”作为新开工门槛。质量评价继续采用用户指定的**Agent质量**：实际操作、画面与反馈、缺陷修复、主审复核，明确截图策略与对话轮次操作的不同证据范围。

独立CLI分发、模型API平台及云端规模化均排在基础作品、素材和嵌入能力之后。M3的本地可分发SDK不等于必须马上商业发布或上线托管。

## M1：三款完整作品

不以增加支持类型数量为目标。已存在的参考作品用于发现引擎/协议问题，不能冒充新一轮独立创作。

| 作品 | 优先提升 | 完整交付 |
| --- | --- | --- |
| G01推箱子 | 有层次的关卡、移动/推箱反馈、动画、撤销、重试、操作说明 | 一组有明确进度的关卡；走错后可理解并恢复；内容、素材、解法/负例和可玩包齐备 |
| G17纵版射击 | 敌机波次、Boss阶段、命中/受击/爆炸反馈、粒子音效、完整节奏 | 准备→战斗→Boss→胜败→重试闭环；普通Agent操作可理解和响应，不以精确解法回放代替操作质量 |
| H01合成炮台保卫战 | 购买/合成/布阵与经济选择、关卡节奏、成长反馈 | 合成/升级对战斗有明确影响，旧对象退出无重复攻击，有策略选择而非只按固定按钮顺序 |

由Qoder、WorkBuddy、TRAE通过现有Skill/MCP分别保留真实独立创作过程；不同宿主不能复用别人的答案充作独立结果。先一个宿主做通一款，再按实际创作安排扩展其余宿主，不提前建立大型全组合验收矩阵。新模型运行按明确预算执行，不继承已耗尽额度。

Capability增强来自这些作品真实暴露的通用缺口。Boss、动画、音效、关卡、撤销等先检索已有能力，缺失时扩展可信通用模块与公开合同；禁止在Adapter按游戏名/ID硬编码玩法。独立原生稿与主审修改版分别记录。

## M2：复用并扩展素材与表现

已有`project/asset-policy.json`、动态内容/资源完整性检查、`src/visual-stage.ts`的Sprite/粒子/音频以及双SDK适配是基础，不重建第二套加载器、可信目录或表现协议。

- 在现有审核目录上增加可检索的2D/3D资源描述，包含用途/风格标签、来源、许可、版本、SHA和字节数；不允许模型自行注册外网资源或执行任意资源脚本。
- 先为三款作品整理少量高质量主题资源：推箱子的场景/角色/目标反馈、射击的飞机/敌人/Boss/命中音效、炮台的等级/攻击/合成反馈。不要求每次从零生成资源。
- 提炼可组合的移动、命中、合成、爆炸、通关等动画/粒子/声音预设；科幻/卡通/像素/自然作为资源与表现参数，不侵入共享玩法逻辑。
- Manifest版本化并保留审核与完整性边界；资源替换、包版本和客户端兼容性一起交付。新增公共能力才同步Schema/合同/Host支持与相关回归，不为每个素材造新能力。

M1与M2循环推进：一款真实作品→发现具体表现缺口→补可复用素材/能力→回到作品验证，而不是先穷尽素材系统设计。

## M3：独立Player SDK

以下仅为**目标API草案**，不是现有稳定接口或兼容承诺：

```js
const player = createA2GamePlayer({
  backend: "cocosairjs",
  container: document.getElementById("game")
});
await player.load(gamePackage);
player.start();
```

从已有Runtime、Player、Adapter提取清晰边界，复用完整准入和可信资源策略：加载/校验、输入、资源作用域、开始/暂停/重开/销毁、业务事件及可处理错误。区分GameSpec、release-bundle和generator-package的接收入口，避免把依赖Python/仓库目录的开发服务误称为浏览器独立SDK。

客户端执行可信内容包，不在加载时隐式调用AI；后台生成端与客户端运行端解耦。首个嵌入样例就验证脱离仓库目录/开发服务的运行条件、所需SDK/资源如何提供，以及load失败或dispose后如何回收。具体模块格式、发布渠道和事件名留到M3依据真实集成需求决定，不提前冻结接口。

## 执行与完成口径

每批只做一条真实正常路径、最相关的关键失败、受影响的已有回归。视觉变更直接看目标画面的开局/交互/终局；明确窄屏问题才追加视口。共享Runtime/协议变更才扩大相关Conformance与双SDK检查。不新增大型测试框架，不追求所有状态×尺寸×Host的全排列。

最终目标：真实Agent从自然语言需求出发，组合可信能力/素材创建完整小游戏，输出客户端能直接加载、运行和持续更新的包。创作、表现、交付三者有实际作品支撑；工程参考、Agent质量、独立生成、真机和正式验收按各自证据记录，未执行即NOT_RUN/BLOCKED。
