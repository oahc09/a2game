# 第二阶段计划：游戏创作与交付

更新日期：2026-11-08。**当前状态：正在开发，部分功能已经可以使用，完整阶段尚未完成。**

## 1. 这一阶段要做什么

让 Agent 不只是生成“能运行”的游戏，还能制作玩法完整、画面清楚、操作顺畅，并能直接交给应用加载的游戏包。

先做好三款代表作品，再补素材和播放器，随后完善版本管理、客户端接入，最后考虑云端服务。已有功能和测试继续使用，不重新搭建一套工具。

## 4. 接下来按什么顺序推进

1. **先处理真实体验问题**：根据Agent试玩，改善操作说明、反应时间、画面和反馈；修复后检查原问题，不重复跑所有游戏。
2. **丰富可复用素材**：围绕三款游戏增加图片、模型、动画和声音。每项素材记录来源、许可、版本和文件摘要，方便检查内容是否被改动。
3. **完善独立播放器**：让业务应用更容易加载游戏，处理输入、暂停、重开、错误和资源释放。
4. **完善版本交付**：支持修改现有作品、增加关卡和回退；之后再处理发布及在线更新。
5. **验证实际客户端**：优先网页，再在可用Android设备上核对操作、音频、切换后台和更新失败时的表现。
6. **最后开发云端服务**：明确模型调用、访问权限和发布方式后，再建设生成接口与资源分发。

已有本地实现可以继续完善，不要求每一步都从头开发。

## 5. 怎样才算完成

三款作品需要能正常操作、完成目标、解释失败原因并重新开始；画面和声音要经过实际观察。游戏包需要能在业务网页中加载，更新时保留旧版，遇到坏包时拒绝使用。

每次修改只做必要检查：一次正常使用、一个直接相关的错误操作，以及受影响的已有测试。修改界面后看实际画面；只有确实出现小屏问题时，再增加小屏检查。不建立所有游戏、所有尺寸、所有状态的庞大组合。

## 6. 阅读测试结论时注意

- **作者路线通关**：按已知操作步骤确认游戏能完成，不等于首次试玩容易理解。
- **Agent质量评审**：Agent实际操作、看画面并反馈问题；看过解法或参与过创作时要说明。
- **正式验收**：继续使用现有G0–G3和37款游戏的标准，不因局部试玩通过而自动升级。
- **没有执行的检查**：写“未测试”；被设备或环境卡住的检查，写清原因。旧记录不代表新版本自动通过。
